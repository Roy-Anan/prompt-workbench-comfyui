# 模型 Profile 智能体执行规范

> 本文件供未来 AI 智能体（或人工）研究绘图模型、生成规则文件、校验规则并提交审核时遵循。工作台只做本地文件管理，不自动联网搜集；模型文件、哈希与资料由人工提供。

## 1. 输入
智能体接收：模型文件路径或 SHA256、模型名称、官方页面链接、作者说明、示例提示词等人工提供的材料。材料不足时允许生成不完整研究报告，但不得伪造结论。

## 2. 研究流程
1. 核对模型身份：名称、版本、基座架构、文件哈希；身份无法确认时标注"未知"，不得凭文件名猜测模型身份。
2. 收集作者说明、官方示例、推荐提示词、触发词与社区经验，每条保留可追溯来源与日期。
3. 分析提示词体系：标签式还是自然描述、组织顺序、质量标签习惯、人物/风格写法、负面策略。
4. 按 `MODEL_RULE_TEMPLATE.txt` 生成规则文件；按 `MODEL_RESEARCH_TEMPLATE.md` 留存研究记录。

## 3. 证据分级（强制）
- **A 已验证事实**：有官方说明、作者资料或明确证据支撑，可写成确定规则。
- **B 高可信经验**：多个可靠示例与独立来源相互印证，可写入但标注经验性质。
- **C 未确认信息**：证据不足、来源不明、存在争议；只能列入"未确认项"，不得写成确定规则。

禁止事项：
- 不得把 C 类信息写成确定规则。
- 不得仅凭模型名称推测提示词特性。
- 不得直接复制其他模型的规则再改个名字。
- 不得删除资料来源与研究日期。

## 4. 生成文件落点
- 待审核规则放入 `staging/<profile-id>/rules.txt`，研究记录一并放入同目录。
- 不要直接写入 `models/`；正式发布必须经过审核流程。
- 规则文件路径由后端安全解析，请求中不得传入任意文件路径。

## 5. 校验清单（提交前自检）
- [ ] 规则套落在 `models/<id>/rules.txt`（id 仅小写字母/数字/`-`/`_`），需要结构化补充时同目录放可选 `meta.json`。
- [ ] 规则文件非空，必需章节齐全。
- [ ] 架构字段有效（`meta.json` 或正文 `Base Architecture`）；checkpoint 匹配模式不与其他 Profile 冲突。
- [ ] 重复 Profile ID 已排查。
- [ ] 路径合法，无 `../`、绝对路径或符号链接越权。
- [ ] 未确认信息已隔离到 C 类，未混入确定规则。
- 目录结构、字段含义与新增流程见上一级 `PROFILES_GUIDE.md`。

## 6. 发布与版本
- 审核通过后由后端把 staging 规则发布到 `models/`，旧版本自动备份到 `archive/`，目录内 `meta.json` 更新版本号；内容哈希读取时实时计算，不手工登记。
- 发布记录来源、发布日期；支持查看历史版本、对比变化与回滚。
- 停用的 Profile 保留文件但不参与 Auto 匹配；删除需二次确认，禁止删除 Core 文件与其他 Profile 的共享文件。

## 7. 隔离与安全
- 模型文件只读：仅用于识别名称、计算哈希、读取元数据；不修改、不移动、不复制权重进工作台目录。
- 不向外部服务发送完整 System Prompt；外部查询只发送完成查询所需的哈希或公开标识。
- 网络不可用时，已安装的 Profile 仍可离线使用。
