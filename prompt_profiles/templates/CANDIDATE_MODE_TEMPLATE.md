# 创作模式（Candidate Mode）参照

> 创作模式与人设 / 题材 / 文风一样，是**目录遍历的文件注册表**：往 `prompt_profiles/modes/` 丢一个 `.txt` 即自动出现在下拉里，文件名（去 `.txt`）同时作为模式 id 与选项名，允许中文。不再需要在前后端与扩展节点四处同步枚举。

## 1. 模式是怎么生效的

- 每个模式对应一句**中文指令（instruction）**，后端组装本次请求时把这句指令拼在 **user 消息末尾**（和现有 Prompt、任务要求、必保术语 / 锁定片段在一起），**不进 system 人设层**。
- 模型仍是同一个本地 Ollama 模型；模式只是用一句话引导这次往哪个方向处理（补全 / 润色 / 精简 / 对照……），工作台侧只做标签去重等后处理，不为每个模式跑不同程序。
- 后端 `mode` 校验走注册表：传了注册表中不存在的值（且不是旧英文别名），直接报 `unknown mode`。
- 模式清单由 `GET /api/modes` 投影给工作台前端、写作助手与 ComfyUI 扩展面板；扩展节点通过只读代理 `modes` 后缀取同一份清单。

## 2. 内置模式清单（`prompt_profiles/modes/`）

| 文件 stem（id 即选项名） | 出现位置 | 指令要点 / 行为 |
| --- | --- | --- |
| `起草` | 提示词工作区、写作助手、扩展节点 | 基于规则与现有内容补全候选，不臆造参数（默认模式） |
| `润色` | 同上 | 在现有内容上润色措辞，保持事实与已规定参数不变 |
| `精简` | 同上 | 去重复冗余，保留核心主体 / 构图 / 已规定参数 |
| `续写` | 同上 | 在现有内容上向后延展补充，承接已有主体与设定，不推翻已有内容 |
| `空白直出` | 同上 | 忽略现有 Prompt，仅按规则与任务从零生成；代码标志 `skip_existing`，拼装时直接跳过现有内容段 |
| `中英对照` | 同上 | 给出中英对照版本，保留语义与已规定参数 |
| `负向词` | 仅提示词工作区、扩展节点 | 补全 / 优化负向词，不改写正向内容；代码标志 `negative_output`，结果走负向输出口，写作页剔除 |

## 3. 新增一个模式：只放一个文件

以「扩写」为例：在 `prompt_profiles/modes/` 新建 `扩写.txt`，正文写一句祈使指令即可：

```
请在现有内容基础上补充细节与层次，保持已规定参数与事实不变；未提供的参数不要臆造。
```

- 保存后注册表热加载，工作台 / 写作助手下拉、扩展节点面板下一次拉取即出现该选项；前端与扩展节点不需要改代码。
- 普通模式结果走正向口、照常携带现有 Prompt，消息拼装不用动。
- 旧版英文 slug（`draft` / `polish` / `trim` / `continue` / `fresh` / `bilingual` / `negative`）由后端 `MODE_LEGACY_ALIAS` 与前端别名表映射到对应中文规范名，历史记录、浏览器记忆与已保存 ComfyUI 图不会失效。

## 4. 需要代码级行为分支的模式（少数，不建议自建覆盖）

绝大多数模式只靠 instruction 一句话引导即可。两个内置特殊行为保留在后端 `MODE_FLAGS`（`backend/prompt_personas.py`）：

- **不携带现有内容**（类似 `空白直出`）：置 `skip_existing=True`；`_user_message` 据此跳过「当前工作流现有 Prompt」段，必保术语 / 锁定片段仍保留。
- **结果走负向输出口**（类似 `负向词`）：置 `negative_output=True`；后端响应带 `mode_negative_output` 标志，工作台前端按身份过滤、扩展节点据此分流到负向口，写作助手页剔除负向模式。

若自建与这两个内置模式同名的文件，只覆盖指令正文，行为标志仍按内置口径生效；不建议这样做。

## 5. 命名与口径约定

- **文件名 stem**：即 id 即选项名，允许中文；不要以 `_` 或 `.` 开头，不要包含 `/ \ : * ? " < > |` 等路径非法字符。
- **正文 instruction**：一句祈使指令，说清这次让模型做什么；保留「未提供的参数不要臆造」这类边界；输出格式 / 语气由人设层管，模式指令里不要重复写围栏、寒暄要求。
- **分类可见性**：写作类适用的模式出现在写作助手页；负向输出模式只在提示词工作区与扩展节点出现。

## 6. 改完自测

- 后端：`.venv\Scripts\python.exe -m pytest backend -q`
- 前端：`frontend` 目录下 `npx tsc -b`、`npx vite build`
- 扩展：`.venv\Scripts\python.exe -m pytest backend/test_extension.py -q`
- 真机：下拉出现新选项；选中后请求体 `mode` 为新文件名 stem，后端不报 `unknown mode`，结果落到正确输出口。
