## 1. 产品定位与目标

ComfyUI Prompt Workbench 是一个面向 Windows 11 的**本机浏览器 Web 工作台**，用于为本地 ComfyUI 工作流编写、优化、审核和管理图像生成提示词。

> **方向变更（ADR-0002，2026-11-18）**：产品正式定为免安装本地 Web 应用，通过本机浏览器访问 `http://127.0.0.1:17890`；不做 EXE/NSIS 安装包，不开发 Tauri/Rust 桌面宿主。ADR-0001 的 Tauri/PyInstaller/NSIS 路线已废弃，仅作历史记录。

- 它不是 ComfyUI 的替代品，也不是通用工作流编辑器；ComfyUI 继续负责模型加载、采样、图像生成和原图保存。
- 工作台负责工作流识别、模型提示词规则、Prompt 创作与安全写入、LLM/显存协调、任务队列、生成记录和 LoRA 资料管理。
- 第一版为单用户、单机、本地运行方案；不接云端 AI API，不要求用户配置云端 API Key，不自动上传用户内容。

## 2. 运行环境

- 操作系统：Windows 11。
- 目标硬件基线：16GB RAM / RTX 4060 Laptop 8GB VRAM（真实显存阈值与释放行为需在真机测量后锁定）。
- 本地外部服务：用户自行安装并启动的 Ollama（本地 LLM）与 ComfyUI（本地出图）；工作台只连接用户配置的本地地址，不替用户启动或关闭这些服务。

## 3. 技术路线（当前 Web 基线）

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 运行入口 | 本机浏览器（Edge/Chrome） | 访问 `http://127.0.0.1:17890`，同源使用前端页面与 API |
| 前端 | React + TypeScript + Vite（构建产物由 FastAPI 托管） | 中文 UI、Prompt 编辑器、候选/草稿/历史/LoRA 页面 |
| 本地业务服务 | Python + FastAPI | 领域逻辑、工作流解析/验证、LLM/ComfyUI 适配、队列、数据访问、静态托管 |
| 数据层 | SQLite + 本地文件 | 本地结构化数据与知识库/草稿/历史文件 |
| LLM 适配 | Ollama Adapter（第一版） | 模型发现、调用、停止、卸载、运行状态验证 |
| 出图适配 | ComfyUI Adapter（HTTP + WebSocket） | 工作流任务提交、事件、历史、队列状态与中断 |

架构为模块化单体，不拆微服务。Python 后端是业务逻辑的唯一权威实现；前端只展示与发起命令，不承担安全边界判断。

> **历史基线记录（已取消）**：早期规划曾采用 Tauri 2.x 桌面宿主 + PyInstaller sidecar 打包；该方向在 TASK-002.3 正式取消，不再继续投入 Rust/Cargo/MSVC/NSIS/EXE 流水线。历史工程文件归档于 `legacy/src-tauri/`，不参与 Web 运行时。
>
> **版本口径**：本机 `.venv` 实测 Python 3.13.18，测试在该版本通过；Python 3.12 兼容性尚未单独验证，未在未测试情况下降级或替换环境。

## 4. 核心模块划分

- 启动脚本与进程生命周期：`workbench_launcher.py` 复用项目 `.venv` 启动 FastAPI、做 loopback/端口/身份校验、健康检查通过后打开浏览器；`workbench_stopper.py` 按身份记录回收本工作台进程树；退出时不影响 ComfyUI/Ollama。
- React 前端：通过本地后端 API 调用业务能力；不直接读写工作流文件、不直连 ComfyUI、不直接控制 Ollama 进程。
- Python 后端：配置与生命周期、工作流解析与白名单、规则与知识库、Prompt 构造与校验、Ollama/ComfyUI/GPU 适配、队列、草稿与历史、SQLite 访问。
- SQLite 数据层：模型身份、规则版本、工作流识别、LoRA 卡片、草稿、生成任务、队列、设置与诊断事件；图片原件、模型权重和原始工作流不入库。
- Ollama Adapter：隔离本地 LLM 运行时细节，统一发现、生成、停止、卸载与状态验证。
- ComfyUI Adapter：HTTP 提交 API workflow、WebSocket 监听事件、queue/history/status 校准、断线重连与中断。
- 知识库与 Prompt 注入系统：角色文件、知识文件、行为规则文件的组织、组合、版本与调用记录（规范见 `docs/PROJECT_CONTROL/INJECTION_SYSTEM_SPEC.md`）。
- 存储管理模块：数据目录配置、备份恢复、SQLite 迁移、文件路径与元数据管理；不复制原图和模型权重进工作台目录。
- 显存管理模块：出图前的 LLM 卸载验证与 GPU 显存状态检查；状态无法确认时安全失败，禁止提交出图。

- 旧项目素材已归档在仓库 `legacy-materials/`，仅供逻辑、规则、交互与边界处理参考。

- 旧素材中的本机绝对路径、模型名、硬件参数仅作历史参考；新项目按实际环境重新配置。

## 6. 工作流安全规则（最高优先级约束）

- 仅允许修改用户确认过的白名单 Prompt 字段（已识别并确认的正向/负向 Prompt 文本）。
- 绝对禁止修改：Checkpoint/VAE/文本编码器等模型选择、LoRA 节点与权重、KSampler 的 Seed/Steps/CFG/Sampler/Scheduler/Denoise、宽高/Batch/Latent 参数、节点类型/数量/ID/连接关系，以及任何非白名单字段。
- 导入时保留原始工作流文件；在独立工作副本或任务快照上工作；写入前保存原始快照并生成结构化差异。
- 差异只能命中白名单字段；任何额外变化立即拒绝；写入后重新解析并校验非白名单字段不变。
- 写入失败停止流程并尽可能回滚；回滚状态不确定时禁止出图。
- 工作流发生变化后旧白名单立即失效，必须重新解析和验证。

## 7. 显存管理规则

- 出图前必须卸载当前 LLM 模型，并验证模型不再处于 loaded/running 列表、显存已释放到安全状态。
- 同时读取 GPU 显存状态；释放状态无法判断或仍高于安全阈值时，阻止提交并解释。
- 不以“请求已发送”作为卸载成功；必须有可观察的状态证据。
- 队列有待执行任务时不提前恢复 LLM；ComfyUI 生成期间禁用 LLM 对话。
- 阈值与验证方式需在真机测量，未测试前不硬编码为保证值；无法确认时状态记为 unknown 并安全失败。

## 8. 存储路径管理

- 工作台默认数据目录位于项目内 `userdata/`（可由 `WORKBENCH_DATA_ROOT` 覆盖）；运行时用户数据与源码隔离，`userdata/` 不纳入 Git 跟踪。
- 模型和原图继续由用户原有目录管理，工作台只记录路径与索引；只扫描用户登记的模型目录，轻量识别不扫描整块硬盘、不加载 GPU 模型。
- 图片原件、模型权重、LoRA、原始工作流不放进数据库，也不复制进工作台数据目录。
- 关键 JSON 快照应记录 `schema_version`；数据库迁移先备份/校验，迁移失败不得静默破坏旧数据；旧数据目录在确认稳定前保留不删。

## 9. 开发阶段（M0–M7，路线图口径）

阶段划分以 `docs/ROADMAP.md` 为准，下列为概览：

- **M0 项目基线与工程准备**：文档/ADR/目录/规范齐备；建立 React + TS + Vite 前端与 FastAPI 本机 Web 骨架；配置检查、测试与本机一键启停入口（Tauri/EXE 方向已取消，见第 3 节）。
- **M1 ComfyUI 连接与工作流解析**：连接配置与重连；导入并解析工作流；识别节点、模型、Checkpoint、文本编码器、LoRA 与正负 Prompt 节点；用户确认识别结果。
- **M2 工作流白名单与完整性保护**：白名单、深拷贝、快照、结构化差异、白名单写入与回滚、写入后复验。
- **M3 模型身份库与规则引擎**：SQLite 身份与 SHA256；三级规则继承；规则版本/来源/可信度；冲突检测与动态检索；云端研究资料导入审核。
- **M4 本地 LLM 接入与 Prompt 工作区**：Ollama 发现/选择/参数/记录；三种创作模式、候选校验、中英文辅助转换、区块编辑、术语保护、语法与 Token 检查。
- **M5 草稿与版本管理**：多草稿、手动保存、环境快照、版本差异与恢复、标签/收藏/搜索/回收站、与历史双向索引。
- **M6 ComfyUI 队列与显存调度**：LLM 卸载与显存验证、任务互斥、队列调度、HTTP 提交与 WebSocket 校准、断线恢复与中断。
- **M7 生成历史**：自动保存 Prompt/工作流/模型/任务快照；记录图片路径与缩略图索引；双视图、搜索筛选导出、反向创建草稿。

> 后续 M8–M10（LoRA 角色卡、数据维护与可靠性、UI 打磨与免安装交付）见 `docs/ROADMAP.md`，本计划不替代路线图。
