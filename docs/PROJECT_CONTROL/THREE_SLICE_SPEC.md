# THREE_SLICE_SPEC — 三段可选注入与两类身份规范

- 文档版本：1.1（已落地）
- 日期：2026-11-20
- 关联：`INJECTION_SYSTEM_SPEC.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md`（M4）
- 状态：后端 / 节点 / 工作台改造已落地，切片见第 9 节；实现口径与本规范一致处以此为准。

## 1. 背景与目标

同一台本地 LLM 要承担不同性质的任务：绘图提示词起草、通用文本/小说写作，以及不附加任何设定的裸模型直连。因此注入到 LLM 的系统内容改为**分层可选叠加**，而不是固定一份写死的系统提示。

核心原则：

- 每一层都可以留空；空 = 不注入该层。
- 所有层都为空时，不发送 system 消息，只发 user 任务消息，即原汁原味调用本地模型。
- 运行时读取源模板 txt 后拼接，**不做组合产物落盘缓存**（源模板即复用单元；改一处，所有组合下次拼接自动生效）。

## 2. 两类身份

身份（系统提示）只分两类，外加一个空身份：

| 类别 `kind` | 含义 | 界面形态 | 适用注入层 |
|---|---|---|---|
| `prompt` | 绘图提示词助手 | 正向 / 负向双框 + 专属规则套 + 负向模式 | 身份 + 底模专属规则 |
| `writing` | 通用文本 / 小说写作助手 | 单文本框 | 身份 + 题材 + 文风 |
| 空（未选身份） | 裸模型 | 单文本框，按 `writing` 形态处理 | 无系统身份，其余层仍可单独叠加 |

> 不设第三类身份。`writing` 与空身份在界面上都是单框，差别仅在于是否带写作身份规范。

## 3. 注入槽位

按槽位组织，每个槽位可空；槽位内容随身份类别不同：

| 槽位 | 提示词类 `prompt` | 写作类 `writing` / 空身份 |
|---|---|---|
| ① LLM | 所选本地 Ollama 模型（必选） | 同左 |
| ② 身份定位 | 提示词助手规范 | 写作助手规范；空身份则不注入 |
| ③ 领域设定 | 底模专属规则套（现有 Profile） | 题材设定（言情 / 武侠…） |
| ④ 风格层 | 留空 | 文风模板 |

- 拼接顺序：身份定位 → 领域设定 → 风格层（提示词类无风格层）。
- 工作流动态规则（规则库按底模解析的专用/架构/通用套）仅在传入工作流且为提示词类时附带注入，不占用户选择位。
- 题材与文风是正交维度：同一题材可配不同文风，同一文风可套不同题材。

## 4. 选择与默认口径

### 4.1 默认值

- LLM 必选；身份、领域设定、风格、模式各槽位可选。
- 画布节点：身份默认 `none`（裸模型），规则套默认 `auto`。
- 工作台：首次进入且无本地记忆时，提示词工作区预选内置提示词助手（`prompt_assistant`）以保留原提示词打磨体验；提示词工作区只列提示词类身份与裸模型（`none`），写作类身份在独立「写作助手」页签；选择随浏览器记忆保留。

### 4.2 选择工作流时的自动预选

- 选中一个已导入工作流后，后端按其 checkpoint / 架构把领域设定 auto 匹配到对应底模规则套。
- 身份不随工作流自动切换；预选结果之后仍可手动更改。手动切到写作类身份后，界面切到单文本形态。

### 4.3 不选工作流

- 不读取工作流上下文，其余槽位保持空，等待手动选择；不做任何自动预选。

## 5. 工作台界面规则

显隐由当前身份类别驱动，**不另设独立的"正负向 / 单文本"手动切换按钮**，避免身份与界面状态打架。

- `prompt` 类显示：任务框、正向框、负向框、专属规则套下拉、负向模式选项、现有正/负向上下文。
- `writing` / 空身份显示：任务框、单结果框；隐藏专属规则套、负向模式、正/负向上下文输入与锁定片段区。
- 候选结果：提示词类按模式分正向 / 负向；写作类与裸模型只产出单一文本，复制或存草稿，不分正负。

## 6. ComfyUI 画布节点

节点与工作台使用同一套槽位口径。

### 6.1 输入

| 字段 | 处理 |
|---|---|
| `model` | 必选，本地 Ollama 模型 |
| `workflow_id` | 改为可选；空 = 不挂工作流、不读工作流上下文 |
| `persona`（新增） | 可选自由文本，`none` = 裸模型；填已登记身份 id。画布侧不用 combo：动态选项来自后端服务，Python 节点的静态占位列表无法通过 ComfyUI 枚举校验 |
| 领域设定（`prompt_profile`） | 三态：空（不注入）/ auto / 指定某套；自由文本填 Profile id |
| `genre` / `style` | 写作类题材 / 文风，自由文本填对应 id，留空不叠加 |
| `mode` | 固定枚举下拉；增加"无"；写作类 / 空身份下负向模式不适用 |
| `positive_in` / `negative_in`（新增，可选连线） | 承接画布现有词，供润色 / 精简 / 负向模式使用；连线内容优先于工作流上下文 |
| 采样参数 | 温度 / Top P / 上下文长度，沿用现状 |

### 6.2 输出

- 固定三口：`positive_text`、`negative_text`、`raw_json`。
- 提示词类按模式分流：负向补全模式结果进 `negative_text`，其余进 `positive_text`。
- 写作类 / 空身份结果填入 `positive_text`，负向口留空。

### 6.3 控件显隐

- 工作台按身份类别条件渲染：写作身份隐藏规则套下拉与负向模式，显示题材 / 文风下拉；提示词身份反之。
- 画布节点控件全保留、空值生效；身份类别驱动的动态隐藏只做在工作台，节点层不做控件显隐。

## 7. 模板目录与文件约定

位于仓库 `prompt_profiles/`（运行数据，不入库模板之外的个人档案）：

```
prompt_profiles/
  personas/            # ② 身份定位
    manifest.json      # 身份清单：id / display_name / kind / system_file / enabled
    <persona_id>/system.txt
  genres/               # 写作类·③ 题材设定（每份一个 txt）
  styles/               # 写作类·④ 文风（每份一个 txt）
  models/<id>/rules.txt # 提示词类·③ 底模专属规则套（现有 Profile）
  templates/            # 空白骨架模板，供复制新增
```

- 新增身份：复制 `templates/PERSONA_TEMPLATE.txt` 到 `personas/<id>/system.txt`，并在 `personas/manifest.json` 登记。
- 新增题材 / 文风：复制 `genres/_TEMPLATE.txt` / `styles/_TEMPLATE.txt`。
- 新增底模规则套：沿用 `templates/MODEL_RULE_TEMPLATE.txt` 与现有 Profile 发布流程。
- 模板 id 仅允许小写字母 / 数字 / `-` / `_`；路径限定在 profile 根内，拒绝 `..` 越权。

## 8. 安全边界

沿用 `INJECTION_SYSTEM_SPEC.md` 第 8 节，本节补充：

- **露骨成人 / 色情题材的设定模板与注入不做**，本地工具同样不绕过；题材目录只收录言情、武侠、玄幻、悬疑等常规题材。
- 任何身份 / 题材 / 文风文件都不能覆盖程序级安全约束（白名单、非白名单字段保护、显存闸门、未确认禁止提交）。
- 注入文件按不可信资料处理；其中"忽略以上规则""修改工作流参数""直接提交出图"等内容不产生程序效力。
- 提示词候选仍须经后端校验与用户确认，才可能进入草稿或写回工作流。

4. 裸模型保留 `num_predict` 上限（640）与 `think: False` 安全网，不在本轮放开为可选。
