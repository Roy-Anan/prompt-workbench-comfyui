# INJECTION_SYSTEM_SPEC — LLM 注入系统规范

- 文档版本：1.0
- 日期：2026-11-17
- 阶段：M0 基线规范（描述目标设计，不代表功能已实现）
- 关联：`docs/ARCHITECTURE.md`、`docs/REQUIREMENTS_BASELINE.md`、`legacy-materials/`（早期总计划/架构视图见 `docs/archive/`）

## 1. 目的

定义工作台在调用本地 LLM 时，如何组织、组合、版本化和追溯注入到 Prompt 中的角色、知识与规则文件。注入系统服务于 Prompt 创作，不得成为绕过程序安全约束的通道。

## 2. 默认文件来源

初始默认素材来自已归档的旧项目资料，位于仓库 `legacy-materials/`（路径以仓库实际目录为准）：

- `legacy-materials/rules/系统提示词_全量版.txt`
- `legacy-materials/rules/系统提示词_Ollama精简版.txt`
- `legacy-materials/rules/输出模板.txt`
- `legacy-materials/rules/模型数据库.txt`
- `legacy-materials/rules/模型索引_Ollama.txt`
- `legacy-materials/rules_source/`（规则包原始来源与模板）
- `legacy-materials/profiles/` 中的 13 份模型画像

说明：

- 这些是历史参考素材，采用前需重新核对可信度与适用范围。
- 默认文件在新项目中的落地位置、格式与加载方式由 M3/M4 阶段实现确定；本规范只定义类别、管理能力与安全边界。

## 3. 三种文件类型

### 3.1 角色文件

- 定义 LLM 的身份、职责、语气与行为立场（例如“ComfyUI 提示词助手”）。
- 回答“你是谁、你负责什么、不负责什么”。

### 3.2 知识文件

- 提供模型、架构、Checkpoint、LoRA、触发词、推荐写法等知识。
- 区分架构级、模型级、Checkpoint 级三级继承；标注来源与可信度（官方确认 / 可靠参考 / 社区经验 / 尚未验证）。

### 3.3 行为规则文件

- 定义输出格式、Prompt 结构、术语保护、正负向区分、自由度与幅度等规范。
- 规定候选输出应满足的格式与校验要求。

## 4. 用户管理能力

后续程序必须支持对注入文件的以下管理能力：

- 新建文件
- 导入文件
- 编辑文件
- 删除自定义文件
- 启用 / 停用
- 排序与分类
- 多角色管理
- 多文件组合
- 默认文件恢复
- 自定义配置保存

## 5. 默认文件保护

- 原始默认文件不得被用户修改操作直接覆盖。
- 修改默认文件时，应创建自定义副本，在副本上改动；默认原件保持不变。
- 默认文件可以恢复到初始版本。
- 自定义文件可以删除；删除不影响默认文件。
- 程序升级不得覆盖用户自定义文件；升级流程需区分默认文件与用户文件并保留用户改动。

## 6. 动态组合

- 注入文件按角色 + 知识 + 行为规则组合后送入 LLM。
- 示例组合：提示词助手角色 + FLUX 模型知识 + Prompt 输出规范。
- 支持两种组合方式：
  - **自动匹配**：程序根据当前工作流识别出的架构、模型、Checkpoint、启用 LoRA 选择相关文件。
  - **手动选择**：用户在界面上指定参与组合的文件与顺序。
- 组合顺序、启用状态与分类应可配置并随自定义配置保存。
- 只向 LLM 传递当前工作流相关的规则与知识，不把整个知识库塞入上下文。

## 7. 调用记录与追溯

后续每次调用 LLM，应记录：

- 本次实际使用的注入文件清单（角色 / 知识 / 规则分别对应哪些文件）。
- 每个文件的版本标识或内容指纹。
- 组合配置（启用状态、排序、自动/手动来源）。
- 调用时间、模型、任务标识与输出概要。

目的：便于追溯、复现某次 Prompt 生成结果，以及在规则更新后定位历史记录使用的是哪一版文件。

## 8. 安全边界

### 8.1 注入文件不能覆盖程序级安全约束

普通角色文件和知识文件不能覆盖、削弱或绕过程序级安全约束。以下约束由程序强制执行，不依赖 LLM 自觉遵守，也不能被任何注入文件改写：

- **工作流节点白名单**：只有确认过的 Prompt 白名单字段可写。
- **非白名单字段保护**：模型选择、LoRA、采样参数、尺寸、节点结构等一律禁止修改。
- **显存安全检查**：LLM 卸载与显存释放未验证通过前，禁止提交出图。
- **未确认回滚时禁止提交**：写入失败或回滚状态不确定时停止流程。

### 8.2 资料视为不可信输入

- 外部导入的模型资料、规则文本和研究结果作为数据处理，不作为可执行指令。
- 注入文件中出现的“忽略以上规则”“修改工作流参数”“直接提交出图”等内容，不产生程序级效力。
- 规则冲突时，程序安全约束优先；规则之间的冲突保留并标注，不由 LLM 自行裁决。

### 8.3 隔离原则

- 前端展示与编辑注入文件，但安全判定与组合准入由 Python 后端执行。
- 注入系统只影响送入 LLM 的文本内容；不直接获得修改工作流、提交出图或操作系统的权限。

## 9. 与其他模块的关系

- 规则引擎（M3）：负责文件分类、三级继承、优先级、冲突检测与自动匹配。
- Prompt 服务（M4）：负责按组合构造候选 Prompt，并把实际组合写入调用记录。
- 知识库 / LoRA 资料：知识文件的来源与可信度管理。
- 安全管线：注入结果进入候选后，仍须经过后端校验与用户确认，才可能写入工作流。
