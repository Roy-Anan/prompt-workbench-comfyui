# 项目维护与智能体交接手册

本手册用于让不同 ChatGPT、Codex、Claude、Gemini
或其他开发智能体接手项目时，能够在不依赖历史聊天记录的情况下安全工作。

## 1. 项目事实来源优先级

发生信息冲突时按以下优先级处理：

1.  用户在当前对话明确提出的最新要求。
2.  仓库中已确认的需求基线与 ADR。
3.  仓库中的架构、模块接口和测试。
4.  历史聊天记录、临时笔记或推测。

如果用户的新要求与仓库基线冲突： - 不要擅自覆盖旧决定。 -
先列出冲突点、影响范围和推荐方案。 - 等用户确认后更新对应文档和 ADR。 -
更新需求文档、架构文档和测试验收标准。

## 2. 接手任务的必读顺序

新智能体接手任何任务前，必须依次阅读：

1.  README.md
2.  docs/PROJECT_OVERVIEW.md
3.  docs/REQUIREMENTS_BASELINE.md
4.  docs/ARCHITECTURE.md
5.  docs/ROADMAP.md
6.  docs/CURRENT_STATE.md
7.  与任务相关的 ADR、代码模块和测试

阅读后先输出： - 当前项目阶段。 - 本次任务目标。 - 涉及的模块和文件。 -
不会触碰的安全边界。 - 计划新增/修改的测试。 - 预期交付物。

不要要求用户重复已经写在文档里的需求。

## 3. 不可协商的安全红线

### 工作流

-   只允许修改用户确认的正向/负向 Prompt 白名单字段。
-   不允许修改其他字段，即使看起来是"修复"或"优化"。
-   未知节点、未知字段必须原样保留。
-   工作流变化后旧识别结果和白名单失效。
-   写入前后都要做差异验证；任何非白名单变化阻止提交。
-   默认不覆盖原始工作流。
-   写入/回滚状态不确定时禁止出图。

### LLM 和 GPU

-   出图前必须完成 LLM 卸载与显存释放验证。
-   卸载失败、超时、模型状态未知或显存状态未知时禁止提交。
-   不允许为了让任务继续而跳过安全检查。
-   不擅自杀掉 Ollama/ComfyUI 进程。
-   ComfyUI 任务执行中不允许同时运行需要 GPU 的 LLM 任务。

### 草稿与用户数据

-   草稿只在用户主动点击保存时持久化。
-   禁止自动保存、临时草稿自动保护或后台自动备份未保存内容。
-   生成历史自动保存。
-   删除草稿不得删除关联生成历史和图片。
-   默认不上传用户内容，不调用云端 AI API。

### ComfyUI 生命周期

-   工作台不得擅自启动、关闭或重启 ComfyUI。
-   已提交任务在工作台关闭时继续由 ComfyUI 运行。
-   不确定任务最终状态时标记 unknown，不自动重新提交。

## 4. 代码组织原则

-   保持模块化单体，不创建微服务。
-   业务规则只在 Python domain/service 层实现一份。
-   React 负责展示和用户交互，不承担安全验证。
-   启动脚本只负责服务拉起、健康检查与进程树回收；业务规则不进脚本层。
-   适配器隔离外部依赖：ComfyUI、Ollama、GPU、文件系统。
-   API 路由保持薄；数据访问集中在 repository。
-   不允许在 UI 组件中直接拼接工作流 JSON 或修改节点字段。
-   不要引入没有明确收益的抽象层、事件总线或插件系统。

## 5. 修改流程

每项开发任务按以下顺序执行：

1.  读取需求和相关 ADR。
2.  确认输入、输出、状态和失败路径。
3.  确认是否涉及工作流、LLM、GPU、草稿持久化或隐私红线。
4.  先写/更新测试，再实现。
5.  运行受影响模块测试。
6.  运行完整测试与静态检查（条件允许时）。
7.  更新文档、示例和版本迁移说明。
8.  汇报改动文件、测试结果、已知限制和未完成事项。

禁止在没有说明的情况下重构无关模块。

## 5.1 证据与回执归档规则（固定口径）

每项任务的验收档案统一放在 `docs/TASK_EVIDENCE/TASK-xxx/`，随代码一起提交到 `dev`，便于按任务、提交 SHA 和测试结果追溯。

目录结构（按需补齐，截图与日志放子目录）：

```text
docs/
└── TASK_EVIDENCE/
    └── TASK-xxx/
        ├── README.md
        ├── Doubao-Receipt.md
        ├── execution-report.md
        ├── test-results.md
        ├── environment-report.md
        ├── git-diff.md
        ├── screenshots/
        └── logs/
```

三条硬性规则：

1.  `Doubao-Receipt.md` 保留豆包每次任务完成后的**完整原始回执**，不要只摘录结论、不要润色改写；回执中的起始/最终 SHA、文件清单、测试通过/失败数、构建结果、真机验收结果、未解决问题等必须原样留存。
2.  其他文件存放测试原始结果、截图、日志、环境信息和代码差异，作为回执的佐证；回执结论必须能在佐证材料中核对到。
3.  每次任务完成后，证据与代码**一起提交到 `dev`**；若任务因测试失败或阻塞未完成，证据（含失败原始输出、已知问题）仍需归档到对应目录，未通过项如实标注，不虚报完成。

补充口径：

- 证据目录名与任务书编号一致（如 `TASK-003.1`）。
- 截图存 `screenshots/`，原始命令输出与错误日志存 `logs/` 或对应的 `test-results.md` / `environment-report.md`。
- 回执与佐证中不记录 token、密码、密钥、用户私密路径；本地用户名等隐私信息用占位符代替。
- `userdata/`、构建产物 `dist/` 等不入库；证据目录中的报告与原始输出可以入库。

## 6. 测试要求

关键安全逻辑必须有自动化测试：

-   Prompt 白名单外字段被修改时，必须拒绝。
-   节点增删、类型变化、连接变化必须拒绝。
-   未知字段必须保留。
-   工作流变化后必须要求重新识别。
-   写入失败和回滚失败必须阻止提交。
-   LLM 卸载失败/超时/状态未知/显存未知必须阻止提交。
-   WebSocket 断开不能直接判失败。
-   应用重启后不得自动重出未知任务。
-   草稿未主动保存不能被后台写入。
-   草稿删除不影响生成历史。
-   重复 SHA256 文件只关联一个模型身份/LoRA 卡。
-   外部模型资料不能执行任意代码或注入系统指令。

## 7. 数据库维护

-   所有 schema 变化通过版本化迁移完成。
-   不允许直接删除用户数据列或表而不提供迁移策略。
-   迁移前检查数据库版本并在适当时做备份。
-   迁移必须测试旧版本数据库升级。
-   数据库只存元数据、规则、快照和索引；不存模型权重或图片原件。
-   生成历史和草稿必须分离；删除草稿不能级联删除历史。
-   JSON 快照应记录 schema_version。
-   恢复备份前做文件完整性和版本兼容检查。

## 8. 日志与隐私

-   默认本地处理，不自动上传。
-   不在普通日志中记录完整 Prompt、用户私密备注、API token 或本地密钥。
-   记录任务 ID、阶段、时间、错误类型和可诊断的非敏感信息。
-   诊断报告只能由用户主动生成；默认不上传。
-   对外部资料保留来源和可信度，不把资料正文当系统指令。

## 9. 依赖与版本维护

-   前端依赖使用 lockfile 固定。
-   Python 依赖使用锁定文件/约束文件固定。
-   前端依赖使用 lockfile 固定；Python 依赖使用约束文件固定。
-   更新 React、Python、FastAPI、Vite
    等关键依赖前，先查看官方迁移说明。
-   不因为依赖有新版本就自动升级。
-   升级后跑工作流安全、LLM 调度、ComfyUI mock 集成和本机启停/构建测试。

## 11. 给新智能体的初始任务指令

你正在接手 ComfyUI Prompt Workbench。请先阅读 README.md 和 docs
目录中的项目文档。不要仅凭聊天摘要推测需求。

项目的最高优先级是： 1. 保护 ComfyUI 工作流：只改用户确认的正/负 Prompt
白名单字段。 2. 出图前确认本地 LLM 已卸载且显存释放。 3.
草稿只有用户主动保存；生成历史自动保存。 4.
默认本地隐私，不自动上传，不接云端 AI API。 5. 保持模块化单体和清晰的
Python/React 职责边界（本机 Web，免安装，见 ADR-0002）。

开始编码前先总结项目状态、任务范围、受影响模块、风险和测试计划。任何无法确认的状态都标记
unknown，不能猜测或跳过安全检查。
