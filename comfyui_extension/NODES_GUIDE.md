# 工作台节点通俗说明（ComfyUI 里怎么用）

这份说明写给日常出图用，不讲代码。工作台扩展一共往 ComfyUI 里挂了
**3 个节点 + 1 个侧边栏面板**。节点都在节点列表的 `Workbench` 分类下。

## 先说前提

- 这些节点本身只是"壳"，真正查规则、生成候选、卸载模型的活儿，都是通过回环地址
  找**工作台后端**（`http://127.0.0.1:17890`）干的。
- 所以**想用工作台节点，先把工作台后端启动起来**（双击 `启动工作台.bat`）。
  后端没开时：节点能拖进画布，但一运行就报"无法读取 / 后端不可达"，属于正常现象，不是节点坏了。
- 节点**只读、不改你的草稿和规则**：在画布上看到的候选和规则文字，不会自动写回工作台；
  要保存的内容仍回工作台网页里操作。
- ComfyUI 和 Ollama 由你自己启停，节点不替你开关进程。

## 节点一览

| 节点（画布显示名） | 内部类名 | 一句话作用 | 什么时候用 |
| --- | --- | --- | --- |
| 工作台规则清单 | `WorkbenchRuleContext` | 按规则层级（底模/架构/通用）把工作台规则库读出来，显示成文字 | 写提示词前，翻翻全局规则本、看看该遵守什么 |
| 工作台释放显存/卸载LLM | `WorkbenchReleaseVram` | 把还驻留在显存里的本地 LLM 卸掉，并释放 ComfyUI 已加载模型占的显存 | 提交出图前跑一次，避免显存被 LLM 占满导致爆显存 |
| 工作台提示词候选生成 | `WorkbenchPromptCandidate` | 让本地 Ollama 模型按选定身份、规则套（或题材/文风）生成一条候选 | 想让 AI 帮你起草 / 润色 / 精简 / 补负向词，或按写作身份起草文本时 |

> 侧边栏面板不是节点：它在 ComfyUI 右侧页签里，只读展示工作流、规则、草稿、素材、
> LoRA、历史的摘要；明细编辑还是回工作台网页。

---

## 1. 工作台规则清单（`WorkbenchRuleContext`）

**大白话**：这个节点帮你"翻全局规则本"。它不绑定工作流，只按规则层级把工作台
规则库里已登记的规则读出来，纯文本浏览，给人写提示词时参考。

### 输入项

| 输入 | 填什么 |
| --- | --- |
| `level` | 规则层级：`checkpoint` 底模层 / `architecture` 架构层 / `global` 通用层 |
| `scope_key` | 规则归属的关键字（一般留空即可） |
| `backend_url` | 工作台地址，留空走默认 `127.0.0.1:17890` |
| `token` | 节点令牌，一般留空；节点会自动读本地凭据文件 |

### 输出项

- `context_text`：整理好的人话文字，可以接到任何文本显示 / 后续提示词节点。
- `raw_json`：后端返回的原始 JSON，排查问题时用，平时不用接。

**注意**：这个节点只读规则，不能在画布上改规则；某层级没有规则时会提示
"当前层级无规则"。

## 2. 工作台释放显存/卸载LLM（`WorkbenchReleaseVram`）

**大白话**：出图前先清场。它会让后端把还挂在显存里的 Ollama 本地模型卸掉，
再让 ComfyUI 释放已加载模型占的显存，然后把卸载结果汇报成文字。

### 输入项

| 输入 | 填什么 |
| --- | --- |
| `enabled` | 开关；关掉就直接跳过、不执行卸载 |
| `backend_url` | 工作台地址，留空走默认 |
| `token` | 节点令牌，一般留空 |

### 输出项

- `status_text`：卸载结果文字（哪些 LLM 已卸、哪些还驻留、ComfyUI 显存是否已释放）。
- `raw_json`：原始结果 JSON。

**注意**：卸载是"尽力而为"。如果后端判断显存不够、或 LLM 没卸干净，提交任务时
工作台的显存闸门仍会兜底拦截，不会硬塞爆显存。

## 3. 工作台提示词候选生成（`WorkbenchPromptCandidate`）

**大白话**：这个节点直接接在你的画布工作流里，不绑定后端工作流。你在节点上
**三段点击选择**——选真实本地 LLM 模型、选 LLM 人设、选模型提示词规则——再让模型
出一条候选。候选只回到画布，不会写进草稿、不会改规则。

### 输入项

| 输入 | 怎么选 |
| --- | --- |
| `model` | 必填。下拉选择真实的本地 Ollama 模型（如 `qwen3:latest`）；扩展会记住上次的选择 |
| `persona` | 人设下拉：`none` 表示不注入身份系统提示词（裸模型），其余选已登记的人设（如 `prompt_assistant` / `writing_assistant`） |
| `prompt_profile` | 模型提示词规则下拉：`auto` 走默认规则，`none` 跳过规则层，其余选已登记的规则套；仅提示词身份生效 |
| `mode` | 创作模式（下拉固定枚举）：`draft` 起草补全 / `polish` 润色 / `trim` 精简 / `bilingual` 中英对照 / `negative` 负向补全 / `none` 无模式指令 |
| `task` | 这次想让它干什么（一句话要求，可留空） |
| `backend_url` / `token` | 同前，一般留空 |
| `genre` / `style` | 写作类题材 / 文风下拉，选对应套件；仅写作身份有意义，留空（`不指定`）表示不叠加该层 |
| `positive_in` / `negative_in` | 可选，把画布上现有的正向 / 负向词一并带给模型做润色补全 |
| `temperature` / `top_p` / `num_ctx` | 采样参数；留默认（`-1`）表示不传给后端，用后端默认值 |

### 输出项

- `positive_text`：带头信息（模式、模型、身份、命中的 Profile / 题材 / 文风）+ 生成的候选；写作 / 裸模型结果也走这一口。**给人看的**。
- `negative_text`：`negative` 负向补全模式的结果（带同样头信息）；其余模式留空。
- `clean_positive` / `clean_negative`：**纯净正文**，不带任何头信息；哪个口有值由 `mode` 决定（`negative` 走 `clean_negative`，其余走 `clean_positive`）。可直接接 CLIPTextEncode，或复制回工作台做安全写入，不会被模式/模型等说明文字污染。
- `raw_json`：后端原始返回。

> 提示：要出图或回写，用 `clean_positive` / `clean_negative`；要当场核对"这是谁、用哪套规则生成的"，看 `positive_text` / `negative_text`。

**注意**：
- `model` 必填；人设、规则套、题材、文风各槽位都可选，人设 `none` + 规则套 `none` 即原汁原味裸模型直连。
- 生成候选这一步会占用本地 LLM；**出图前记得再跑一次"释放显存/卸载LLM"节点**，
  别让 LLM 和出图模型同时占显存（本机 8GB 显存尤其要注意）。

## 一条典型连线（参考）

```text
工作台规则清单 ──context_text──▶ （人看 / 接到后续文本节点）
工作台提示词候选生成 ──clean_positive──▶ CLIPTextEncode 正向文本
                    └──clean_negative──▶ CLIPTextEncode 负向文本
                    （positive_text / negative_text 留给人核对来源）
出图前：工作台释放显存/卸载LLM ──status_text──▶ （确认显存清场后再提交出图）
```

实际使用中，节点之间不强制串联；规则清单和候选生成是"看图写词"环节，
释放显存是"提交出图"环节，按你自己的流程摆即可。

## 常见问题

- **节点列表里找不到 `WorkbenchRuleQuery` / `WorkbenchWorkflowContext`**：
  这两个旧节点已合并成 `WorkbenchRuleContext`（工作台规则清单）。旧画布若保存过
  这两个旧节点，会显示为缺失节点，删掉后重新拖一个新节点即可。
- **节点运行报后端不可达 / 502**：工作台后端没启动，或地址不对。先开 `启动工作台.bat`；
  确认后端在 `127.0.0.1:17890` 后再运行节点。
- **在节点里改的内容会存下来吗**：不会。节点只回显候选和规则，草稿、规则、素材的
  增删改都在工作台网页里做。
- **节点会动 ComfyUI 里的别的节点或参数吗**：不会。扩展只通过后端受控接口读规则 /
  生成候选 / 触发卸载；工作流的其他节点、Seed、尺寸、CFG、Steps、LoRA 权重都不碰。
